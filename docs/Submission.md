# Submission Guidelines
## Game Concept and Design Document
Submit one Game Concept and Design document (PDF).

Your document should include:

1. Game title
2. One-sentence game idea
3. Intended player experience
4. Core mechanic
5. What the player does moment to moment
6. Target player
7. Reference games or inspirations
8. What is original or creative about your idea
9. Vertical slice plan
10. Must-have, should-have, could-have, and cut-first features
11. Unity development plan
12. Main systems/scripts you expect to build
13. Asset/resource plan
14. Legal, ethical, social, accessibility, and security considerations where relevant
15. Development schedule or milestone plan

Your Report should explain:

1. Design choices
2. Technical decisions
3. Problems and limitations
4. Testing and what changed because of testing
5. Reflection on how the game developed from concept to final version
6. Personal contribution
7. Use of templates, assets, tutorials, or AI support

For the Game + Report part, your submission should show:

1. A playable and stable vertical slice
2. Clear player experience
3. Appropriate use of game systems such as input, game logic, interaction, audio, animation, physics, collision, UI, and AI where relevant
4. Sound programming decisions
5. Evidence of testing, debugging, and improvement
6. Legal, ethical, social, accessibility, and security considerations where relevant
7. Clear connection between your design plan and final result

For the Game Demo / Presentation part, you should prepare to:

1. Explain the game and its goals
2. Demonstrate the main features confidently
3. Explain important design decisions
4. Explain important programming/technical decisions
5. Answer questions honestly and thoughtfully
6. Present professionally

The Game Demo / Presentation will be assessed live. You must still upload your presentation slides, demo plan, or recording link here as supporting evidence.

Do not submit only a Unity project folder and assume it is playable.

You must submit either:

1. A playable build, or
2. A clear download link to a playable build.

If you also provide the Unity project or GitHub link, make sure the README explains how to open and run the project.

Do not upload unnecessary Unity folders such as Library, Temp, Obj, Logs, or very large build-cache folders unless specifically required.
